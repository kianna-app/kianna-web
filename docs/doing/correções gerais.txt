Heads-up para o deploy
Backend (Railway) — variáveis novas:

ZAPI_BASE_URL (opcional, default https://api.z-api.io)
ZAPI_CLIENT_TOKEN (opcional agora; obrigatório ao usar Z-API de verdade)
APP_URL (opcional, default https://www.kianna.com.br)
ZAPI_WEBHOOK_TOKEN (já existia — mantido)
Frontend (Vercel) — nada novo. Os endpoints /api/whatsapp/* apontam para o backend via environment.apiUrl que já existe.

Supabase — você já rodou o SQL da PR1, então está pronto.

Riscos de subir agora
Nenhum dos fluxos atuais quebra se Z-API não existir — todos têm guard de null/.catch. O único "barulho" será logs warn se o webhook receber algo (mas sem ZAPI_WEBHOOK_TOKEN o webhook nem aceita).

Pode subir tranquilo. Depois é só:

Criar conta em z-api.io
Criar uma instância (por profissional)
Settar ZAPI_CLIENT_TOKEN no Railway
Configurar webhook na Z-API apontando para https://kianna-api-production.up.railway.app/api/webhooks/zapi com header x-zapi-token: <ZAPI_WEBHOOK_TOKEN>
Profissional cola Instance ID/Token nas configurações e clica "Conectar"

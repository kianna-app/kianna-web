# Planejamento Estratégico — Melhorias e Ajustes da Plataforma
## Contexto
Este documento organiza, estrutura e detalha os pontos de melhoria identificados na plataforma de agendamento, com foco em:

* Eliminar ambiguidades
* Definir comportamento esperado
* Antecipar problemas técnicos e de UX
* Facilitar a criação de taskcards executáveis
* Permitir implementação orientada por IA (Claude Code)
* Considerar aprendizados da análise estratégica de concorrentes

# Objetivo Principal

Criar taskcards claros, executáveis e sem ambiguidades, contendo:

* Contexto funcional
* Objetivo da funcionalidade
* Regras de negócio
* Fluxos esperados
* Possíveis problemas
* Critérios de aceite
* Sugestões de implementação

# Diretrizes Gerais

## Antes de implementar qualquer item

* Validar impacto na experiência do usuário
* Considerar escalabilidade futura
* Evitar retrabalho estrutural
* Definir regras de negócio explícitas
* Garantir consistência visual
* Considerar versão mobile
* Validar integração entre módulos

# Terminologia

* *Profissional* -> Refere-se ao nosso cliente, pessoa que irá cadastrar a empresa em nosso sistema
* *Cliente* - Refere-se ao cliente na empresa que irá agendar os serviços

# 1. Dashboard → Visão Geral

## Objetivo

Transformar o dashboard em uma visão rápida e estratégica do negócio do usuário.

## Itens Identificados

### Cards principais

* Próximos agendamentos
* Total de agendamentos no mês
* Agendamentos do dia
* Quantidade de cancelamentos
* Taxa de ocupação (futuro)

## Melhorias Estratégicas

### Ênfase no link público da empresa

O link público deve ser um elemento de destaque visual.

### Objetivo

Estimular compartilhamento e ativação do negócio.

## Sugestões

* Exibir URL pública da empresa
* Botão copiar link
* Botão visualizar site
* CTA visual forte

## Possíveis Problemas

* Usuário não entender importância do link
* Slug mal configurado
* URL muito longa

## Critérios de Aceite

* Usuário consegue copiar o link em 1 clique
* Link fica visível no dashboard
* Responsivo no mobile

## Funcionalidades

* Preview da URL
* Botão “Visualizar seu site”
* Copiar URL

## Perguntas Pendentes

* Usuário poderá alterar slug futuramente?
* Quantas vezes?
* Alteração impactará SEO/link compartilhado?
* Precisamos redirecionamento automático?

## Possíveis Problemas

* Colisão de slugs
* URLs ofensivas
* SEO quebrado
* Links antigos inválidos

# 5. Cadastro de Serviço

## Objetivo

Permitir criação estruturada de serviços oferecidos.

## Campos Necessários

### Obrigatórios

* Título do serviço
* Descrição
* Valor
* Duração

## Modalidades do Serviço

### Opções

#### Presencial

Cliente vai até o estabelecimento.

#### Visita domiciliar

Profissional vai até o cliente.

#### Remoto / Online

Atendimento remoto.

## Perguntas Estratégicas

* Serviço pode possuir múltiplas modalidades?
* Modalidade altera disponibilidade?
* Modalidade altera preço?

## Sugestão Técnica

Usar enum:

```ts
PRESENCIAL
DOMICILIAR
ONLINE
```
